# Предложение — тому, кто решает

Прототип **Тех 2**, команда «Рэд флаг» №54, кейс-школа Альфа-Будущего.

Четыре поля профиля меняют продукт, адресата, текст и визуал, приоритет каналов и частоту. Правила объясняются кодами Ф1–Ф2, К1–К5, Л1–Л3. Это демонстрация доработки существующего оптимизатора, а не новый банковский сервис.

## Открыть

Скачайте репозиторий и откройте `index.html`. Сервер, установка зависимостей и ключи не нужны. Все шрифты и изображения находятся в `assets/`.

## Сценарии

1. **Клиент 1:** холдинг из пяти юрлиц. Одно предложение собственнику в «Альфа-Босс». Роль «операционист» переключает превью на его интернет-банк и даёт «Отправить руководителю». После передачи можно открыть предложение как собственник и запросить один расчёт группы.
2. **Было / Стало:** пять условных одинаковых баннеров против одного группового предложения. «Было» — иллюстрация, не снимок банковской системы.
3. **Клиент 2:** письмо финдиректору АПК → тот же текст на лендинге → 30 млн ₽ на 9 месяцев в калькуляторе → заявка. Низкая цифровая активность делает КМ первым каналом.
4. **Клиент 3:** начатая заявка → пауза 45 с или 3 возврата → закрываемая подсказка → завершение. Для ускорения есть явно подписанные кнопки имитации сигналов. Подсказка показывается один раз за сессию.
5. **Условия и ограничения:** нет согласия, отказ, исчерпан лимит, два предложения без реакции, нет ёмкости КМ или ценности контакта → сейчас не отправляем.

Данные и действия условные. Нет отправок сообщений, банковских заявок и CRM-интеграций. Тексты новых сочетаний не генерируются: показывается подача по К4, как предписано шпаргалкой. Черновики подписаны.

## Vercel

Импортируйте этот GitHub-репозиторий в свой аккаунт Vercel. Настройки уже находятся в `vercel.json`: сборка `node scripts/build.cjs`, папка результата `dist`, переменные окружения не нужны. Платный тариф и внешние API не требуются для локальной работы; условия размещения определяются аккаунтом Vercel.

Для локальной сборки и проверки:

```sh
npm test
npm run check
node scripts/compare-strategies.cjs
npm run build
```

## Устройство

- `data.md` — исходная шпаргалка команды, включая таблицы, без перефразирования.
- `data.js` — три условных профиля, точные тексты и параметры пилота.
- `rules.js` — одна таблица правил, чистая функция решения и защита от дублирования действий.
- `app.js` — интерфейс, переходы, формы, однократная помощь и локальные события.
- `dataset-summary.js` — только агрегаты анализа выгрузки.
- `docs/dataset-report.json` — отчёт по пяти CSV и ограничения данных.
- `scripts/analyze_data.py` — воспроизводимый анализ; исходные выгрузки передаются локальным путём и в Git не включаются.
- `docs/strategy-comparison.json` — сравнение трёх способов реализации на 14 сценариях приёмки. Это не замер бизнес-эффекта.

Исходный HTML кабинета использован как визуальный референс. Он содержал реквизиты и операции, поэтому сам HTML и его данные не включены в репозиторий. Логотип кейс-школы взят из материалов организаторов; оформление используется для учебной защиты, без заявления об официальном сервисе банка.

Материалы для защиты: [сценарий и заметки](docs/DEMO.md), [проверка требований](docs/REQUIREMENTS.md), [отчёт QA](docs/QA.md), [видео 70 с без звука](docs/demo-tech2.mp4).

Для повторного анализа CSV распакуйте три вложенных архива в локальную папку и выполните `python scripts/analyze_data.py /путь/к/распакованным/данным` из корня проекта. Скрипту нужен Python с pandas; для открытия самого прототипа Python не требуется.
